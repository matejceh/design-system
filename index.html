Overview

Design System

A shared language for design and development — covering Halcom's mobile and web products.

What is a Design System?

A design system is a collection of reusable design decisions, components, and guidelines that define a shared design language across teams. It connects design and development through a single source of truth — from foundational tokens like colors and typography, all the way to fully-documented UI components ready for implementation.

Design Tokens Colors, typography, spacing, shadows — the foundational values that define the visual identity.
Components Buttons, inputs, cards, navigation — documented UI building blocks with usage guidance.
Guidelines Clear rules for when and how to use each component — keeping decisions consistent across the team.
Code CSS snippets and token values ready to use — no guessing, no reinventing the wheel.

Why are we building one?

01 Consistency Every screen feels like it belongs to the same product — same colors, spacing, and interactions, regardless of who built it.
02 Speed Stop recreating solutions that already exist. Pick a documented component, apply it, move on. More time for features that matter.
03 Brand quality The app always looks and feels like Halcom — on iOS, on Android, across every feature. Brand is built into the system, not added on top.
04 Team alignment Designers and developers share the same language. A component name in a mockup maps directly to a token or code snippet — no interpretation gap.
05 Scalability As the product grows, the system grows with it. Adding a new screen means assembling existing parts — not starting from scratch.

Color tokens

Use tokens instead of raw hex values. Pressed states are generated automatically with color-mix(). Semantic colors carry specific meaning — success is non-text only.
